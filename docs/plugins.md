# Плагины Ovygram

С чего начать — [руководство по плагинам](guide.md) и
[шаблон проекта](../tools/ovygram/template). Перенос плагинов с Android —
[отдельная страница](porting-android.md).

Описание аккаунтов, сообщений, файлов, событий и хуков находится в
[документации SDK этапа 3](sdk.md), собственный интерфейс плагинов и доступ
к интерфейсу Telegram — в [документации `desktop.ui`](ui.md).

Сборка `plugins` для Windows x64 включает CPython 3.13.16 и pybind11 3.0.2.
Архивы закреплены по SHA-256 в `tools/ovygram/python_bundle.py`.
[Манифест CPython для Windows](https://www.python.org/ftp/python/3.13.16/windows-3.13.16.json).
Откройте «Настройки → Плагины» и импортируйте
[пример lifecycle](../tools/ovygram/examples/lifecycle.ovyplugin).
Выберите его в списке и нажмите «Включить». Страница плагина находится
внутри настроек Telegram. На ней появятся переключатель, поле ввода
и список выбора. Изменения применяются кнопкой «Сохранить настройки».
Пример записывает запуски и выгрузки в журнал.

Карточка в списке показывает версию, автора и краткое описание. Переключатель
управляет запуском, нажатие на название открывает страницу плагина. Кнопка
«Отправить» открывает стандартный выбор чата и подтверждение файла. Для ZIP
используется исходный архив. Чтобы отправить ZIP, установленный в более ранней
сборке, сначала обновите плагин из исходного архива. Кнопка «Удалить» требует
подтверждения.

Плагин — это `<id>.ovyplugin` (один файл) или `<id>.ovyzip` (архив).
Файлы `.py`, `.plugin` и `.zip` импортируются локально по тем же правилам,
но на проверку и в репозиторий плагинов принимаются только `.ovyplugin` и
`.ovyzip` с именем по ID. Полные правила — спецификация
`plugin-distribution.md` в репозитории `ovygram-info`.

Файл объявляет литералы `__id__` (латинские буквы, цифры и `_`, до 25
символов, приводится к нижнему регистру), `__name__`, `__description__`,
`__author__`, `__version__` (до 15 символов, числа через точку, буквенный
суффикс только после точки: `1.2b`), `__release__` (`True` или `False`),
`__platform__ = "desktop"` и `__desktop_sdk__ = 2`. Каждый метатег
объявляется ровно один раз простым присваиванием, иначе файл отклоняется.
`__requirements__` перечисляет сторонние библиотеки с PyPI, клиент ставит их
при включении плагина (см. [зависимости](dependencies.md)); без библиотек его
можно опустить или оставить пустым.
Точка входа объявляет один класс, наследующий `base_plugin.BasePlugin`.

Архив содержит в корне `plugin.json` ровно с полями `id` и `entry`,
например `{"id": "chat_tools", "entry": "main.py"}`, сам файл и ресурсы.
Абсолютные пути, `..`, повторы имён без учёта регистра, имена устройств
Windows, ссылки и ZIP-бомбы отклоняются. Соседние модули подключаются
относительным импортом, например `from .helpers import format_text`.
Путь к ресурсам начинается от `Path(__file__).parent`.
Предел архива и распакованных данных — 32 МиБ, основного файла — 1 МиБ.

Импорт читает метаданные, а код запускается при включении плагина.
`on_plugin_load` и `on_plugin_unload` вызываются в главном потоке.
`create_settings` возвращает список `Switch`, `Input`, `Selector`
из `ui.settings`. Методы `get_setting` и `set_setting` работают
с общими настройками конкретного плагина, `log` пишет в журнал.
Каждая установка — отдельный экземпляр со своим `installation_id`: к нему
привязаны настройки, данные (`get_plugin_data_dir`), обработчики, меню и
ошибки. При импорте файла с уже установленным ID клиент предлагает обновить
существующий экземпляр, установить новый отдельно или отменить. Обновление
сохраняет `installation_id`, настройки и данные; менеджер хранит предыдущую
версию для отката. Обновлённая или восстановленная версия ждёт включения.
Перед запуском клиент сверяет SHA-256 установленного пакета и распакованные
файлы: изменённый на диске плагин не запустится.

Плагины, установленные до появления экземпляров, переносятся
автоматически со своими настройками и данными. Они сохраняют старый ID
(например `desktop.weather`); новую версию с ID по новым правилам клиент
установит как отдельный плагин.

Настройки и журнал хранятся в `plugins/` внутри рабочего каталога клиента.
Если предыдущий сеанс оставил аварийный маркер, плагины остаются отключёнными
до нажатия «Возобновить запуск плагинов». Параметр `--disable-plugins`
запрещает запуск плагинов до следующего запуска без этого параметра.
Плагины работают в процессе Telegram, поэтому включайте только доверенные
файлы. Зависший обработчик может заблокировать окно.

GitHub Actions запускает краткую проверку в режиме `plugin-smoke`.
Режим `plugins` повторяет её перед оптимизированной Release-сборкой и упаковкой ZIP.
Для воспроизведения используйте стандартный runner с тем же закреплённым
компилятором и существующими кэшами зависимостей. ZIP использует тестовые
API credentials Telegram, как и базовая сборка этапа 1.
