# Сторонние библиотеки плагинов

Плагин перечисляет нужные библиотеки с PyPI в `__requirements__`:

```python
__requirements__ = ["qrcode[pil]>=8.2,<9", "pillow>=11"]
```

Клиент устанавливает их, когда пользователь включает плагин, и запускает
плагин после установки. Пример — [QR-код текста сообщения](../tools/ovygram/examples/qr_code.ovyplugin).

## Что можно указать

Каждая строка — имя пакета, необязательные extras и условия на версию:
`requests`, `requests>=2.31,<3`, `qrcode[pil]==8.2`. До 32 строк по 200
символов. Ссылки, пути к файлам, маркеры окружения (`; sys_platform == ...`)
и параметры pip не принимаются: зависимость может выбрать только версию
пакета с PyPI.

Ставятся только готовые wheels: пакеты на чистом Python и бинарные пакеты,
собранные для Windows x64 или Linux x64 и CPython 3.13. Пакет, у которого на
PyPI есть только исходники, не установится — компилировать на машине
пользователя клиент не будет. Проверить заранее можно так:

```
pip download --only-binary=:all: --python-version 3.13 --platform win_amd64 --no-deps ПАКЕТ
pip download --only-binary=:all: --python-version 3.13 --platform manylinux2014_x86_64 --no-deps ПАКЕТ
```

## Как это работает

- Все плагины используют **одно общее окружение**: каталог
  `plugins/dependencies/<id>` в профиле клиента. Он добавляется в конец
  `sys.path`, после стандартной библиотеки и SDK, поэтому библиотека плагина
  не может их подменить.
- При включении плагина pip разрешает зависимости **всех включённых
  плагинов** и нового вместе. Если версии несовместимы, установка
  прерывается, а на карточке плагина видна ошибка pip, например
  `ResolutionImpossible`. Библиотеки уже работающих плагинов при этом не
  меняются.
- pip запускается **отдельным процессом** из встроенного Python и wheel
  pip 26.2.2, который поставляется с клиентом. Интерфейс не блокируется;
  пока идёт установка, на карточке написано «Устанавливаются зависимости».
  Одновременно идёт одна установка. Настройки pip (`pip.conf`, переменные
  `PIP_INDEX_URL`, прокси) учитываются.
- Каждая установка создаёт новый каталог. Если в нём те же версии пакетов,
  что уже используются, он подключается сразу и плагин запускается. Если
  версия используемого пакета изменилась, новый каталог подключится **после
  перезапуска** клиента: загруженный модуль, особенно нативный, нельзя
  заменить в работающем процессе. Клиент сообщает об этом в разделе плагинов.
- Библиотеки выключенных плагинов остаются в окружении до следующей
  установки и удаляются при запуске клиента вместе с неиспользуемыми
  каталогами.

Вывод последнего запуска pip сохраняется в
`plugins/dependencies/install.log`.

## Ограничения

- Нужен доступ к PyPI или к индексу из настроек pip.
- Если зависимость перестала устанавливаться (например, удалили профиль
  или окружение), плагин не запустится с сообщением «Зависимости не
  установлены»: выключите и снова включите его.
- В сборке с `OVYGRAM_SYSTEM_PYTHON` используется системный
  `python3.13`; wheel pip поставляется и в этом режиме.
