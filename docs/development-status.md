# Состояние Ovygram

Дополнение от 13 ноября 2026 года: поверх `e5f788c` реализованы проверка
доверия, диалог установки с ограничениями Plugin API, обновления и обработка
блокировок. Добавлены меню профиля, Header/Button настроек и собственные
кнопки в нативных панелях `chat.top_bar`/`compose`, SDK и пример `panel_buttons`.
Последний Python-прогон: 158 тестов, 156 прошли, 2 нативных пропущены.
Новые C++ изменения не компилировались: Windows-сборка — только GitHub Actions
по отдельной команде владельца, сборка Linux сейчас также не поручена.
Полная защита системных окон от произвольного кода отложена на будущее:
[protected-ui-architecture.md](protected-ui-architecture.md). Отдельная модель
разрешений не предусмотрена, настройки и данные принадлежат `installation_id`.
Ключ Ed25519 закреплён; адреса API/индекса будут назначены при развёртывании.
Подробности — [plugin-distribution.md](plugin-distribution.md), API кнопок —
[ui.md](ui.md). Ниже сохранён исторический статус SDK от 7 ноября.

Обновлено 7 ноября 2026 года.

Исходники основаны на Telegram Desktop v7.3.5, коммит
`3a2a9a34e833d3243a13787215b8a7cdcf5dc3c3`. Изменения ядра плагинов
и обновление основы объединены без конфликтов Git.

## Подготовлено в исходниках

- Встроенный CPython 3.13.16 через pybind11 3.0.2, менеджер плагинов в
  штатных настройках Telegram, импорт, включение, отключение и откат.
- SDK 2: аккаунты, загруженные данные и история, отправка, редактирование,
  удаление и пересылка сообщений, загрузка и скачивание файлов.
- События сообщений, аккаунтов и чатов; прикладные RPC-хуки и обработка Updates.
- Генератор 2578 TL-конструкторов и методов, кодек и объявления для редактора.
- Управляемый asyncio, таймеры, фоновые операции и диспетчер главного потока.
- [Документация SDK](sdk.md) и пять [примеров](../tools/ovygram/examples).
- Этап 4, интерфейс плагинов ([документация](ui.md)): диалоги, окна,
  холсты, полосы в чате, страницы в основной колонке, пункты главного меню,
  меню чата и сообщения, именованные элементы Telegram, доступ к виджетам
  через Qt, сочетания клавиш, строка ввода, декорации и скрытие чатов,
  декорации сообщений, цвета темы, события окон и сигналы Qt
  (`desktop.native`), [справочник точек перехвата](hooks.md).
- Linux x64: встроенный CPython собирается из исходников, libssl, libffi и
  libsqlite3 берутся из системы; параметр `OVYGRAM_SYSTEM_PYTHON`.
- Исправления по аудиту кода (PR #4).
- Этап 5: [сторонние библиотеки](dependencies.md) из `__requirements__` —
  общее окружение, установка отдельным процессом через встроенный pip,
  только готовые wheels, явные конфликты версий, перезапуск при смене версий.
- [Руководство](guide.md) по привычной структуре, [шаблон проекта](../tools/ovygram/template)
  с автодополнением и сборкой архива, `.pyi` для `desktop.ui`,
  `desktop.native` и утилит, [перенос Android-плагинов](porting-android.md).

## Проверка

Предыдущая личная сборка ядра плагинов на основе v7.3.3 проверялась на Windows.
Это не проверка новой версии Ovygram. Для переименованных исходников v7.3.5
прошли 44 локальных Python-теста на CPython 3.13.16; один тест нового нативного
хоста пропущен, поскольку его DLL не собиралась.

Сейчас нет собранного и проверенного Ovygram с SDK 2. Следующим шагом должны
стать компиляция C++, запуск portable-пакета в отдельном профиле и проверка
аккаунтов, хуков, файлов и выгрузки плагинов в настоящем Telegram-сеансе.
До такого запуска нельзя считать этап SDK 2 завершённым.

## Перед публичным выпуском приложения

Нужны собственные API credentials, отдельная иконка и окончательная проверка
названия приложения, уведомлений Windows, сохранности данных и совместимости
плагинов. Исходники содержат ресурсы upstream для дальнейшей адаптации;
открытие репозитория не является выпуском готового приложения.

Этап 4 проверяется в клиенте по [чек-листу](ui-checklist.md). Указанные здесь
как отсутствующие 7 ноября кнопки добавлены 13 ноября; их визуальная проверка
остаётся открытой до новой сборки.
